# 第三方社区验证案例：GSQ + KVMem rc3，RTX 4080 16GB

本案例不再使用仓库维护者早期的 QQZ/rc2 性能数据。当前案例来源是 GitHub 用户 **RiskManager6** 在 2026-09-22 提交到 KVMem 上游仓库的实测报告：

- 原始 issue：[kvmem/kvmem-llama.cpp#47](https://github.com/kvmem/kvmem-llama.cpp/issues/47)
- 关系：该报告引用并扩展了本仓库维护者此前的 #22 测试，但测试数据、脚本和复测由对方自行提交。
- 定位：**第三方社区验证**。本仓库引用这些结果，但不把它们描述为维护者自己的 benchmark。

## 测试环境

| 项目 | #47 报告环境 |
|---|---|
| GPU | NVIDIA GeForce RTX 4080 16GB |
| CPU / 内存 | Intel Core i5-13600K / 32GB DDR5-6000 |
| 系统 | Windows 11 23H2 |
| KVMem | v0.16.0-rc3 Windows CUDA 13.2.86 预编译包 |
| 模型 | Qwen3.8-27B-GSQ-RCO IQ3_S MTP |
| Vision projector | Q5_K-MIX，CPU 运行 |
| GPU fallback 策略 | NVIDIA prefer no system-memory fallback |

测试前显存环境经过清理，因此不应把下面的吞吐直接外推到所有日常桌面环境。

## 60K 检索案例

报告使用约 60K token 的合成检索提示，并将目标值放在上下文中部。

| 指标 | 结果 |
|---|---:|
| Prompt token | 60,084 |
| Prefill | 1,204 tok/s |
| Decode | **52.6 tok/s** |
| 中部埋点检索 | 成功 |
| 同请求缓存复用 | 60,083 / 60,084 prompt token 命中 |
| 整卡显存峰值 | 15,115 MiB / 16,376 MiB |

这组结果支持将 GSQ IQ3_S 作为 16GB 档位的主要泛用模型候选，但仍然只是单一硬件/软件环境的社区测试。

## 9/9 K/V 量化组合

#47 对 q4_0、q5_0、q8_0 的 K/V 组合做了完整 3×3 矩阵测试。每组均包含短题、约 32K token 中部埋点检索以及同请求缓存复用。

汇总结果：

- **9/9 组合均可正常启动和推理。**
- 9/9 均完成目标检索和缓存复用。
- Prefill 范围约 **1362–1383 tok/s**。
- Decode 范围约 **54.6–59.1 tok/s**。
- 报告中的整卡显存峰值约 **14.3–14.8 GiB**。
- 在该测试范围内，没有观察到某个 K/V 组合带来数量级的速度差异。

这些数据用于说明 rc3 + GSQ IQ3_S 在该平台上的量化兼容性，不用于声明所有模型、所有上下文长度都有同样表现。

## 128K / 100K-token 后续测试

随后对方又补测了 128K 上下文：

| 指标 | 结果 |
|---|---:|
| 配置上下文 | 131,072 |
| 实际 prompt | 100,084 token |
| Prefill | 1,173 tok/s |
| Decode | **56.5 tok/s** |
| 中部埋点检索 | 成功 |
| 重复请求缓存命中 | 100,083 / 100,084 |
| 整卡显存峰值 | 14,777 MiB / 16,376 MiB |
| 系统可用内存最低 | **2,571 MB** |

因此，#47 在 32GB 系统内存机器上证明了该 GSQ/rc3 配置可以完成一次 100K-token 级检索任务。不过系统内存余量已经较小；报告者没有继续尝试 192K，并将 128K 视为这台机器的实际高档位。

本仓库因此继续把 **64K** 作为更保守的默认档，同时把 **128K** 保留为有外部实测支持但需要关注内存余量的高档位。

## CPU 多模态验证

#47 还使用 CPU 侧 Q5_K-MIX projector 做了一个合成图片识别 smoke test：

- 图片内容识别正确。
- Prompt 约 190 token。
- Decode 约 **64.8 tok/s**。
- 语言模型继续完整驻留 GPU，projector 在 CPU 侧运行。

这为 GSQ 的“泛用 + 多模态默认”定位提供了独立社区证据。

## 与本仓库当前固定配置的差异

引用此案例时必须保留以下边界：

- #47 使用 **KVMem rc3**；本仓库当前下载资产仍固定在其自身已记录的运行时版本，除非另行升级并重新验证。
- #47 使用 **Q5_K-MIX projector**；本仓库当前默认资产仍固定 F16 projector。
- #47 在测试前主动清理显存，并设置 prefer-no-sysmem-fallback。
- 该案例没有覆盖长期多轮 Agent 稳定性、并发客户端或 192K/256K。

因此，本案例是对 **GSQ + KVMem 路径的第三方社区验证**，而不是本仓库当前每一个固定组件的逐项复现。
